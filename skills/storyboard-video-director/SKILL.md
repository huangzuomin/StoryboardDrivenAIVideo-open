# Storyboard Video Director

## Purpose

Use this skill as a pre-generation director and compiler for AI video work. Convert the user's idea into a structured director pack; do not directly generate final videos in the MVP workflow.

Core principle: design how to shoot first, then let image or video models generate.

Creative principle: when the user gives a sparse or non-professional idea, do not merely restate it. Upgrade it into the strongest professional storyboard interpretation that fits the subject, genre, and intended emotional effect. Act like a senior storyboard director: infer identity, rhythm, technique, motif, camera escalation, and payoff when the user has not supplied them.

## Critical Stop Rules

- Ordinary requests such as "help me design a 15s clip" are preflight production requests, not text-plan requests, unless the user explicitly says "text only", "only prompt", or "do not generate assets".
- When another generic video skill also matches, prefer this skill for pre-generation planning, storyboard-first packs, visual storyboard assets, reference assets, Seedance/Veo handoff prompts, or any request that says the output is for later video generation. Generic video-generation skills should only take over when the user asks to actually render final video clips now.
- Requests that say "storyboard plan", "before video generation", "visual storyboard", "storyboard sheet", "fan/sleeve action", or use `rhythm_performance_board`, `body_driven_transformation`, `storyboard_heavy`, `12_panel_rhythm_sheet`, or `16_panel_action_sheet` require a real `storyboard_control` image for preflight. A storyboard prompt file alone is not enough.
- `storyboard_control` for preflight/final delivery must be a raster image (`.png`, `.jpg`, `.jpeg`, `.webp`) generated by image2/image generation or supplied by the user. SVG/programmatic diagrams can be kept as schematic/route maps, but they do not satisfy `storyboard_control` by themselves.
- For product-lock/object-lock requests, missing real `prop_reference` or `storyboard_control` images is not a future recommendation; it is the current blocking work. Before any final response, either generate/register those images or state that image generation is unavailable/blocked.
- If the built-in `image_gen` tool is available and the user did not forbid asset generation, use the `imagegen` skill and call image generation for the required central assets. Generate the product/prop reference first, then the storyboard control image.
- Do not final with only "next step: generate images" for an ordinary product-lock or high-motion storyboard request. That is an incomplete task handoff, not a completed response.
- Before final response, run `scripts/validate_expected_delivery.py <package_dir> --profile preflight`. If it fails, continue into visual asset generation or report a true blocker.
- Asset requirements are strategy-specific, not generic. Product/object-lock needs real `prop_reference` plus `storyboard_control`; face/emotion flow needs a readable `character_reference`/expression asset plus close-enough storyboard; spatial rescue/route action needs `environment_reference` plus Segment storyboard controls; high-motion performance needs body/prop motion boards and final payoff protection.
- For production/final handoff, `clean_keyframe_reference` should be real generated/user-supplied images when the strategy recommends it. Prompt-only clean keyframes are acceptable for iteration, but must be disclosed as a gap.

## Workflow

1. Parse the request.
   - Identify story type, main subject, location, core actions, emotional tone, visual style, target duration, video model, and whether the user already supplied a shot structure.
   - Treat ordinary user phrases such as "design a short video", "make a 15s product clip", "product film", "ad film", "ready for AI video generation", "plan this as a video", "video prompt", or "short clip" as storyboard-video-director triggers when the user is asking for a controllable generated-video plan.
   - For these normal video-design requests, default to creating or updating a director pack. Do not stop at a single prose prompt unless the user explicitly says they only want one prompt and no pack/files.
   - If details are missing, infer professional defaults instead of asking repeated questions. Use conservative safety assumptions, but ambitious creative assumptions.
   - Record user hard constraints before adding professional inference: target duration, subject identity, location, required final payoff, visual style, and explicit exclusions. Professional inference may enrich these constraints but must not silently replace them.
   - Treat requests for a visual storyboard, storyboard sheet, storyboard image, drawing the storyboard, or generating a storyboard image as a request for a visible storyboard image asset, not only a text table, prompt pack, or ready-to-run image task.
   - Set a mental `visual_storyboard_requested = true` flag when those phrases appear. The final response must include or link a generated storyboard image saved under `11_generated_storyboards/`, unless image generation is genuinely unavailable or blocked and the blocker is stated explicitly.
   - For a new plain-language brief that needs a pack scaffold, use `scripts/create_pack_from_brief.py --brief "<user brief>"` to create a first-pass pack and `16_user_preview_summary.md`.

2. Extract story energy.
   - Summarize the driving force, such as investigation pressure, ritual exhaustion, disaster rescue, escape/surveillance, public responsibility, or emotional release.

2a. Apply the production asset pipeline when the user asks for a short video, product clip, ad, AI-video-ready plan, visual storyboard, or production handoff.
   - Read `references/production_asset_pipeline.md`.
   - Treat the task as storyboard-first production workflow, not prompt writing.
   - For product-lock or recurring-object tasks, plan or generate the prop/product reference before storyboard control and before downstream video prompts.
   - Do not call a pack production-ready just because package or manifest validators pass.
   - Set a mental `expected_delivery_profile`: use `preflight` for ordinary user requests to design a short video/product clip/AI-video-ready pack, and `final` for production handoff or expensive generation.
   - `text-plan` is not an inferred fallback. Use it only when the user literally asks for text-only planning, no generated assets, or only a prompt draft.
   - Product-lock/object-lock preflight or final responses require real generated or user-supplied `prop_reference` and `storyboard_control` image assets. Prompt files alone are not an acceptable user-facing completion.

3. Run the Professional Inference Pass.
   - Use this especially when the user prompt is short, generic, or not written like a director's brief.
   - Decide the strongest genre interpretation of the idea.
   - Infer subject-specific technique vocabulary, movement grammar, or workflow logic.
   - Create a memorable subject identity when useful: name/codename, silhouette, costume anchor, signature object/color, emotional posture, and final self-definition.
   - Define one dominant visual motif system that organizes the board, not just decoration: moving shape, repeated graphic pattern, escalation, and final transformation.
   - Define the rhythm engine: music BPM, beat count, timestamps, breath rhythm, edit pulse, impact cadence, or silence pattern.
   - Define the final payoff: held pose, reveal, statement, punchline, transformation, or emotional release.

4. Run the Control Strategy Router.
   - Decide whether the scene is best controlled by storyboard, face/emotion coordinates, character sheets, environment maps, style references, clean keyframes, or a hybrid.
   - Use storyboard-heavy control for action, group staging, transformations, rescue, chase, sport, dance, product sequences, and spatial continuity.
   - Use product-lock / object-lock control for product videos where the product must remain identical across shots. Pair it with storyboard control for operation order and prop/product reference assets for identity, scale, materials, buttons, slots, ports, labels, and forbidden mutations.
   - Use face/emotion-heavy control for inner conflict, monologue, restrained dialogue, micro-expression, singing mouth shapes, and psychological states.
   - For fan, sword, sleeve, ribbon, rope, fabric, bat, or kata-like weapon/prop performance, prefer a hybrid of `rhythm_performance_board` and `body_driven_transformation`; add `object_lock` or a prop reference when the recurring prop must stay consistent.
   - Choose a storyboard layout by scene type when a board is appropriate: 3x3 action grid, 4-panel horizontal dialogue flow, 4x3 trailer grid, 3x4 product board, 12/16-panel rhythm-performance sheet, or transformation strip.
   - For Segment metadata, separate `control_mode` from `execution_mode`. Example: a jump-rope Segment can use `control_mode: rhythm_performance_board` and `execution_mode: single_continuous_shot`; an inner-emotion Segment can use `control_mode: face_emotion_flow` and `execution_mode: single_continuous_shot`.
   - State reference priority explicitly: storyboard controls order/staging/timing; character references control identity; environment references control geography/light; style references control finish; clean keyframes control final-frame look.
   - Identify soft-hint risk: current video models may prioritize cinematic appeal over exact storyboard adherence, so add adherence boosters when fidelity matters.
   - Apply strategy-specific asset requirements:
     - `product_lock` / `object_lock`: generate/register product or prop reference before storyboard control; lock shape, scale, ports/buttons/states, and forbidden mutations.
     - `face_emotion_flow`: generate/register a character or expression reference with readable face states; storyboard panels must be close enough to control eyes, jaw, mouth corners, breath, and final mask.
     - `rhythm_performance_board` / high-motion action: generate dense action/rhythm storyboard controls; include body-driven prop logic, movement qualities, timing snapshots, and final held payoff.
     - `spatial_route_action` / rescue/chase/route: generate both route/geography reference and Segment action storyboard; lock start, hazards, destination, return path, and prop/rope continuity.
     - `body_driven_transformation`: show before, trigger, mid-change, and payoff states; transformation must arise from body/prop action rather than unexplained magic.
   - Write the decision into `00_control_strategy.md` when creating a production pack.

5. Plan duration and Seedance2 segments.
   - Read `references/rhythm_pacing_knowledge.md` before estimating target duration, Segment count, Beat density, or panel count.
   - Read `references/storyboard_genre_patterns.md` before choosing panel count for performance, sport, dance, music-video, action, chase, comedy, rescue, or product transformation.
   - Read `references/performance_control_systems.md` when the request involves singing, facial acting, inner conflict, dance, martial arts, prop choreography, transformation, or body-driven performance.
   - Create a pacing diagnosis before writing the duration plan: genre energy, audience felt speed, target duration, average Beat duration, fastest Beat, slowest Beat, required pauses, and Segment split reason.
   - Do not under-panel rhythm showcases. For high-motion performance subjects, default to 12-16 panels unless the user asks for a minimal board. Use 16 panels when the appeal depends on technique escalation and visual rhythm.
   - Treat one Seedance2 generation as one 5-15 second Segment.
   - Split anything over 15 seconds into multiple Segments.
   - Keep each Segment to 2-5 Beats; high-motion Segments should usually be shorter and use fewer Beats.
   - If a story is split into multiple Segments, each Segment must have its own independent annotated storyboard control prompt and, when storyboard images are generated, its own storyboard image. Do not use one shared multi-Segment storyboard image as the direct control reference for multiple downstream video generations.
   - A global storyboard sheet may exist for human overview only; downstream video agents such as xyq should receive the Segment-specific storyboard image for the Segment they are generating.

6. Build the Visual Bible.
   - Define subject identity, costume/body language, location, lighting logic, environment elements, visual texture, camera language, motif system, annotation system, and avoid list.
   - Reuse this consistently in storyboard, keyframe, and video prompts.
   - For professional storyboard language, load `references/cinematic_storyboard_language.md`.
   - For fan/weapon/prop performance, include an emotion model, Laban movement qualities, and explicit body-driven prop logic unless the project is deliberately static.

7. Build the Beat Storyboard Plan.
   - Use Beat IDs `P01`, `P02`, etc. and Segment IDs `S01`, `S02`, etc.
   - Each Beat must include its Segment, role, shot size, technique/action phrase, subject action, camera movement, composition, environment change, motif progression, emotion, and clean keyframe prompt.
   - For high-motion stories, load `references/motion_action_vocabulary.md` and make every Beat show direction, momentum, impact/transition, and reaction.
   - For `rhythm_performance_board`, each Beat should include timestamp or beat count, music/rhythm function, technique escalation, camera escalation, and one short expressive director note where useful.

8. Generate the production pack.
   - Use `scripts/scaffold_package.py` to create the output structure when writing files.
   - When updating an older pack, run `scripts/upgrade_manifest_schema.py <package_dir> --write` before validation so legacy manifest fields are upgraded instead of hand-patched.
   - Produce the standard files listed in `references/output_contract.md`.
   - Fill `00_control_strategy.md` before writing the detailed Segment plan.
   - For multi-Segment packs, put each Segment storyboard prompt in `05_segment_storyboard_prompts/Sxx_storyboard_prompt.txt`.
   - Put each Clean Keyframe prompt in its own `06_clean_keyframe_prompts/Pxx.txt`.
   - Put each Seedance2 prompt in its own `07_seedance2_segment_prompts/Sxx.txt`.
   - In `10_generation_manifest.json`, fill `user_hard_constraints`, `reference_assets`, and Segment-level `control_mode` / `execution_mode`.
   - Create or update `14_review_status.md` and `14_review_summary.md` so future review can inspect the pack quickly.
   - For genre-specific storyboard sheets, load `references/storyboard_genre_patterns.md`.
   - When identity, costume, hair, sleeve volume, or central prop consistency matters and no character reference is supplied, run `scripts/build_character_reference_prompt.py <package_dir>` to create prompt-only character/prop reference assets and update the manifest.
   - When geography, platforms, water, stairs, routes, action lanes, or repeated landmarks matter and no environment reference is supplied, run `scripts/build_environment_reference_prompt.py <package_dir>` to create a prompt-only environment reference asset and update the manifest.
   - When final render finish, line quality, color grade, texture density, or lens tone matters and no style reference is supplied, run `scripts/build_style_reference_prompt.py <package_dir>` to create a prompt-only style reference asset and update the manifest.
   - When clean final-frame/keyframe image references are needed, run `scripts/build_clean_keyframe_image_tasks.py <package_dir>` to create one image task per clean keyframe prompt and update `clean_keyframe_reference`.

9. Validate the result.
   - Run `scripts/validate_package.py <package_dir>` after creating a pack.
   - For newly generated packs, run `scripts/validate_manifest.py <package_dir>/10_generation_manifest.json --strict-current-schema` to ensure current-schema fields are present.
   - Run `scripts/diagnose_pack_readiness.py <package_dir> --profile preflight` for ordinary requests, or `--profile final` before production handoff, and treat its recommended next actions as the current task list.
   - Add `--allow-prompt-only-product-lock` only when the user explicitly asked for text-only planning; never use it for ordinary production/preflight/final delivery.
   - Run `scripts/validate_expected_delivery.py <package_dir> --profile preflight` before any ordinary short-video/product-clip final response. Use `--profile final` for production handoff, and add `--visual-storyboard-required` when the user asked for a visible storyboard sheet.
   - Never run `validate_expected_delivery.py --profile text-plan` for an ordinary request such as "help me design a 15s clip"; text-plan requires `--explicit-text-only-request` and a literal user request for text-only output.
   - If expected delivery validation fails, either generate/register the missing visual assets or state image generation is blocked. Do not say "done", "ready", "handoff-ready", or "已设计好" as the main conclusion.
   - Treat validators as structure/schema checks only. They do not replace visual asset generation, visual asset QC, or strict asset QC.
   - For production deployment or expensive generation, run `scripts/preproduction_orchestrator.py <package_dir> --phase final`; final phase requires real generated/user-supplied assets for all manifest roles that are not marked `not_needed`.
   - Run `storyboard-video-qc/scripts/preflight_qc.py <package_dir> --strict-assets` when deciding whether a pack may enter video generation. This checks strategy-specific semantics such as face readability, body-driven motion, route clarity, and prop continuity.
   - Fix structural issues before presenting the result.
   - Run `scripts/build_review_summary.py <package_dir>` after validation to update `14_review_status.md` and `14_review_summary.md`.
   - When the user asks to review, compare, 复盘, or learn from the learning pack, run `scripts/review_against_learning_pack.py <package_dir>`.
   - Read `references/quality_checklist.md` and run the storyboard excellence checks before finalizing any storyboard prompt.

10. Generate the annotated storyboard image when requested.
   - This stage is optional only for text-only director packs. It is mandatory when `visual_storyboard_requested = true`.
   - Enter this stage when the user explicitly asks to generate storyboard images, call images2, proceed from prompt pack to image output, or asks for a visual storyboard/storyboard sheet.
   - For production-ready product-lock or recurring-object requests, also generate or register the product/prop reference image before treating the storyboard/video prompt as handoff-ready. If image generation is unavailable, report the blocker and leave concrete image tasks rather than claiming completion.
   - Read `references/image_generation_workflow.md` before invoking an image agent.
   - For a single-Segment pack, use `scripts/build_storyboard_image_task.py <package_dir>` to create one concise images2 agent task.
   - For a multi-Segment pack, run `scripts/build_storyboard_image_task.py <package_dir> --segment-id Sxx` once per Segment, and generate one independent storyboard image per Segment.
   - Save returned images under `11_generated_storyboards/` and write a short review note in the same directory.
   - Use image2/image generation for accepted storyboard controls. Programmatic SVG boards may be generated as auxiliary schematics or route maps, but they must not be the only `storyboard_control` asset for preflight/final handoff.
   - If the image tool saves to a default/generated-images directory, copy the accepted image into `11_generated_storyboards/` and leave the original in place.
   - After saving the image, update `10_generation_manifest.json` `reference_assets.storyboard_control.path` and `status`, then run `scripts/build_review_summary.py <package_dir>`.
   - Before the final response, run `scripts/check_visual_storyboard_delivery.py <package_dir>` when `visual_storyboard_requested = true`; do not close the task until it passes or you clearly state why image generation is blocked.

11. Build the final video-generation prompt.
   - Read `references/video_generation_prompt_workflow.md`.
   - For a complete director pack, use `scripts/build_video_generation_prompt.py <package_dir>` to create `12_video_generation_prompt/video_generation_prompt.txt`, `video_generation_prompt_full.txt`, and `video_generation_prompt_concise_seedance.txt`.
   - Use `scripts/build_video_generation_prompt.py <package_dir> --mode concise_seedance` when the downstream model benefits from a shorter Seedance-style control contract.
   - If a generated storyboard image exists, pass it with `--storyboard-image`.
   - This prompt is platform-neutral and should be reviewed before uploading assets or submitting to a video agent.

11a. Run the one-click preproduction orchestrator when the pack already exists and needs to be prepared for review or handoff.
   - Use `scripts/preproduction_orchestrator.py <package_dir>` to upgrade the manifest, create prompt-only character/prop/environment/style asset prompts, build clean keyframe image tasks, build the final video prompt, validate the package, refresh review summaries, and run preflight QC.
   - Use `--phase iteration` only for early drafting work, and add `--explicit-text-only-request` only when the user literally asked for text-only planning. Ordinary user video-design requests should use `--phase preflight`.
   - Use `--phase preflight` for default ordinary user requests before test generation. This is the default profile and now fails product-lock/object-lock packs that lack real `prop_reference` or `storyboard_control` images.
   - Use `--phase final` for final handoff or expensive generations. It automatically enables `--strict-assets`, requires visual storyboard delivery, and runs a final asset gate that requires every manifest reference asset not marked `not_needed` to be real `generated` or `user_supplied` media.
   - In `--phase final`, the orchestrator also runs `scripts/build_generation_handoff_bundle.py <package_dir>` to create `17_generation_handoff/asset_manifest.json`, `video_prompt_for_upload.txt`, and `handoff_readiness_report.md`.
   - Use `--visual-storyboard-required` when the user asked for a visible storyboard sheet; this must fail if no image exists under `11_generated_storyboards/`.
   - Use `--storyboard-image`, `--character-image`, `--prop-image`, `--environment-image`, and `--style-image` to register generated or user-supplied images into the manifest before QC.
   - Use `--clean-keyframe-dir` to register a directory of generated clean keyframe images into the manifest before QC.
   - Use `--strict-assets` for final production readiness or expensive generations. This turns missing or prompt-only central assets into blockers through storyboard-video-qc.
   - Default mode writes a concise Seedance prompt; pass `--mode full` only when a longer platform-neutral handoff is needed.
   - The orchestrator refreshes `16_user_preview_summary.md`; read it before composing the chat response.

12. Optionally prepare video-generation handoff.
   - Only enter this stage when the user asks to generate video, use xyq, or hand off a pack to a video agent.
   - Read `references/reference_asset_workflow.md`.
   - Prefer `17_generation_handoff/video_prompt_for_upload.txt` and `17_generation_handoff/asset_manifest.json` for production video generation handoff because they avoid local absolute paths and expand directory assets into uploadable image files.
   - Create or update `13_xyq_video_handoff/asset_manifest.json` with storyboard, character, environment, style, and clean keyframe references.
   - Use the reviewed `12_video_generation_prompt/video_generation_prompt.txt`.
   - Run `scripts/build_xyq_video_task.py <package_dir>` to create `13_xyq_video_handoff/xyq_video_task_message.txt`.
   - When using xyq-nest-skill, upload the referenced files, update asset IDs in the manifest, then submit the generated task message.

## Segment Modes

Choose one mode per Segment:

- `single_continuous_shot`: dance, body performance, psychological pressure, immersive movement, emotional release.
- `coherent_multi_shot_sequence`: advertising, city promo, product display, news-like explainer, multi-angle space coverage.
- `motivated_camera_changes`: disaster rescue, chase, investigation, action, documentary field pressure.
- `match_cut_sequence`: emotional escalation, product transformation, time passage, music video rhythm, matched posture/action transitions.
- `rhythm_performance_board`: sport-performance, dance, music-video, martial arts form, stage act, skating, parkour, jump rope, drumming, runway, or any movement where rhythm is the product. Use visible beat logic, technique escalation, motif repetition, timestamps or beat counts, and expressive director notes.
- `face_emotion_flow`: monologue, dialogue, restrained acting, singing close-up, inner conflict, or psychological shift where facial continuity and emotion coordinates matter more than spatial staging.
- `body_driven_transformation`: ribbon, fan, fabric, magic, product assembly, costume change, or any transformation where the visible body/action must trigger the changing shape.

For detailed rules, read `references/segment_rules.md`.

## Output Rules

- Annotated Storyboard is for control and review. It may contain arrows, panel labels, and colored annotations.
- Accepted `storyboard_control` assets must be raster storyboard images from image2/image generation or user-supplied images. SVG diagrams are allowed only as auxiliary schematic/route-map references.
- For user-facing chat replies, read `references/user_facing_handoff_template.md` and prefer a compact production summary over dumping internal prompt/schema details.
- When `16_user_preview_summary.md` exists, use it as the main index for what to show the user.
- If the user asked for a visual storyboard/storyboard sheet, the deliverable is incomplete until an actual storyboard image exists under `11_generated_storyboards/` or a blocking reason is reported. A prompt file alone is not sufficient.
- If the user asked to design a short video, product clip, ad, or AI-video-ready plan, the default deliverable is a director pack with storyboard/control strategy, manifest, reference asset roles, and downstream prompt/handoff artifacts. A single video prompt alone is incomplete unless explicitly requested.
- Product or recurring-object videos must include product/object lock in `03_visual_bible.md` and `prop_reference` in the manifest. If no product reference image exists, create a prop/product reference prompt under `11_reference_assets/`.
- Validator pass is not production readiness. Production readiness requires real central assets, strict asset QC, visual asset review, and a handoff prompt built from registered assets.
- Premium hand-drawn action storyboards are allowed and encouraged for high-motion performance when the user asks for visual storyboard quality. They should be rough, masterful, directional, and readable, not polished cover art.
- Rhythm performance boards should make rhythm visible through timestamps, beat marks, repeated motif shapes, technique escalation, and final payoff. Keep text sparse enough for image models.
- For multi-Segment video generation, the direct `storyboard_control` asset must be Segment-specific. A shared overview storyboard can support human review, but it must not be the only storyboard control asset sent to downstream video agents.
- Clean Keyframes are for generation reference. They must not contain arrows, text, panel labels, borders, or annotation marks.
- Seedance2 prompts are per Segment, not per Beat. Reference frames must be described as ordered visual beats inside one coherent segment.
- Manifest is the execution layer. It must be valid JSON and trace Segments to Beats, keyframes, prompt files, and transitions.
- Manifest must distinguish `control_mode` from `execution_mode` when those differ, and must record `reference_assets` with role, path, and status.
- Generated storyboard images are optional review artifacts. Do not feed them as clean video references unless the user explicitly accepts the annotation artifacts.
- Video handoff messages must explicitly state each reference asset's role. Do not collapse storyboard control, character identity, environment continuity, and style into one vague reference.

## Boundaries

For the default MVP flow, do not render final videos, edit final video, create music, or create subtitles. Visual reference asset generation is allowed when the user asks for visual storyboard output, generated assets, production-ready handoff, or when product-lock consistency makes the visual asset loop central to the request. If image generation is unavailable, clearly report the blocker and produce concrete image tasks. If the user explicitly asks for video generation or xyq handoff, prepare the reference asset manifest and task message first, then follow the requested video tool's own instructions.
